## 4. Механизм zigzag

Один конечный автомат. Бары 1h в порядке времени, поля **high** и **low** (не close). R = 0.10 константа. Пропусков не склеивать и не заполнять.

### 4.1 Состояние

На любом шаге:

- `direction` ∈ {`UP`, `DOWN`} — текущий **неподтверждённый** свинг.
- `extreme` — экстремум этого свинга (цена).
- `extreme_bar` — индекс бара, на котором этот экстремум напечатан (при равенстве — более поздний бар, потому что обновление идёт `>` / `<`, не `>=` / `<=`).
- `pivots[]` — список **подтверждённых** пивотов `{kind: H|L, price, bar_index}`. Неподтверждённый текущий экстремум в `pivots` **не** входит.

### 4.2 Seed (один, без лишних констант)

Бар 0 (первый бар серии K-0 в окне):

- `direction = UP`
- `extreme = bars[0].high`
- `extreme_bar = 0`
- `pivots = []`

Первый подтверждённый пивот — **swing high**, когда сработает разворот вниз от этого high. Другой seed не вводить.

### 4.3 Шаг на баре t (порядок обязателен)

Сначала текущее направление, **один проход**. Второй проход по тому же бару не изобретать. Если high и low одного бара могли бы и продлить экстремум, и дать разворот — правило = порядок ниже.

**Если `direction == UP`:**

1. Если `bars[t].high > extreme`: `extreme = bars[t].high`, `extreme_bar = t`.
2. Затем разворот: если `(extreme - bars[t].low) / extreme >= 0.10` — подтвердить **swing high** в точке `(extreme_bar, extreme)`; `direction = DOWN`; новый `extreme = bars[t].low`; `extreme_bar = t`.

**Если `direction == DOWN`:**

1. Если `bars[t].low < extreme`: `extreme = bars[t].low`, `extreme_bar = t`.
2. Затем разворот: если `(bars[t].high - extreme) / extreme >= 0.10` — подтвердить **swing low** в точке `(extreme_bar, extreme)`; `direction = UP`; новый `extreme = bars[t].high`; `extreme_bar = t`.

R считается от **текущего** `extreme` (цены экстремума свинга). Не от длины предыдущего свинга. Не от close.

Деление на `extreme`: на BTCUSDT цены > 0; отдельную ветку `extreme == 0` не добавлять.

### 4.4 Что не делать в zigzag

- Не close-zigzag.
- Не ATR, не k баров, не fractal N.
- Не пропускать gap-бары и не интерполировать дырки (`n_gaps=29` остаются).
- Не подтверждать пивот в конце серии «потому что окно кончилось»: висящий экстремум без разворота R=0.10 — не пивот.
- Не второй параметр.

`n_swings` = число **подтверждённых** пивотов в `pivots` на окне K-0 (и H, и L). Число в этом файле не снималось.

## 5. 5-count + фильтры S-1 §5.1

Пивоты zigzag чередуются H/L по построению автомата §4.

### 5.1 Структура кандидата

**5-down** — шесть подряд пивотов `H0, L1, H2, L3, H4, L5`:

- W1: H0 → L1 (вниз)
- W2: L1 → H2 (вверх)
- W3: H2 → L3 (вниз)
- W4: L3 → H4 (вверх)
- W5: H4 → L5 (вниз)

**5-up** — зеркало `L0, H1, L2, H3, L4, H5`.

Подтверждение L5 (соответственно H5) — тот бар, на котором zigzag-разворот **запирает** этот экстремум (сработал R=0.10 против него). Этот бар подтверждения — **первый** бар, на котором 5-count может быть помечен завершённым.

Кандидат оценивается, когда в `pivots` появляется новый пивот и длина ≥ 6: берутся **последние шесть** подряд. Если они H-L-H-L-H-L — кандидат 5-down; если L-H-L-H-L-H — кандидат 5-up. Лишних окон/k не вводить.

### 5.2 Цитаты S-1 §5.1 (не переписывать S-1)

Фильтры D-1 — **только** этот список; авторство zigzag к Андрееву не приписывать:

- W2 падающего импульса «ушла ниже основания волны 1» → импульс снят
- W4 падающего импульса «зашла в территорию волны 1» → импульс снят
- 3 волны ≠ 5 (коррекция, не импульс)
- нечитаемо / боковик / «запил» → не пятёрка

### 5.3 Неравенства (лаборатория штаба, зеркало Elliott; не «глаз Андреева»)

**5-up (классика):**

- W2 не ниже основания W1: `L2 >= L0` (лой отката W2 не печатается ниже старта W1).
- W4 не в территории W1: `L4 > H1` (нет overlap с ценовым диапазоном W1).

**5-down (зеркало, то что нужно S-1):**

- W2 не дальше основания W1: `H2 <= H0` (хай отката W2 не печатается выше старта W1). Это зеркало графика «W2 не ниже основания W1».
- W4 не в территории W1: `H4 < L1` (хай W4 не перекрывает W1, которая кончилась в L1).

Оба фильтра обязательны. Иначе кандидат структурно может быть шестипивотовым, но **не** `5-down` / **не** `5-up`.

### 5.4 Когда фильтр не прошёл

Если 5-count **структурно** завершился (шесть пивотов нужной ориентации), но W2 или W4 не выполняется:

- метка события `unreadable` (не `5-down` / не `5-up`);
- счётчик `n_rejected` += 1;
- payload `5-down` / `5-up` не эмитить.

Ранний съём (не ждать L5/H5), тот же `n_rejected`, тот же `unreadable` на баре события:

- 5-down: при подтверждении H2 если `H2 > H0`; при подтверждении H4 если `H4 >= L1`.
- 5-up: при подтверждении L2 если `L2 < L0`; при подтверждении L4 если `L4 <= H1`.

### 5.5 Три волны ≠ пять

Если есть только три направленных плеча (ABC), пятёрку не ждать.

Операционально, **незаконченный** 5-down: суффикс пивотов `H0, L1, H2, L3` есть, L5 этой шестёрки ещё не подтверждён. На любом следующем баре, пока кандидат не завершён как шесть пивотов:

- если `bars[t].high >= H0` — цена сняла основание W1; это **3 ≠ 5**, не импульс.
- метка бара `unreadable`; **не** `5-down`; **не** ждать W4–W5 на этой тройке.
- `n_rejected` **не** увеличивать (это не filter-failed пятиструктура; см. §8).
- событие идёт в `n_unreadable`.

Зеркало, незаконченный 5-up (`L0, H1, L2, H3`, H5 не подтверждён): если `bars[t].low <= L0` → 3 ≠ 5, то же.

После 3 ≠ 5 эта тройка мертва как кандидат; zigzag продолжается; следующий кандидат — следующая естественная шестёрка пивотов.

## 6. Метка бара

На каждом баре t **ровно одна** метка:

| label | смысл |
| --- | --- |
| `none` | нет действующего **прошедшего фильтры** 5-count; неполный zigzag ещё рисуется; либо после события-отказа уже прошли последующие бары без новой завершённой пятёрки |
| `5-down` | последний завершённый count — **прошедший** 5-down |
| `5-up` | последний завершённый count — **прошедший** 5-up |
| `unreadable` | на этом баре произошёл отказ: filter-fail, 3 ≠ 5, либо конфликт двух ориентаций |

### 6.1 Payload `5-down` (обязателен)

Пока метка `5-down`:

- `high_w2 = H2`
- `high_w4 = H4`
- `low_w5 = L5`
- origin для будущей инвалидации S-1 (if/then S-1 здесь не менять): `H0`, `L1`

Это то, что S-1 потом возьмёт для наклонки 2–4 и стопа под лой 5. D-1 наклонку **не** считает и ордер **не** ставит.

Payload `5-up` (для hour-rule S-1 позже): `low_w2 = L2`, `low_w4 = L4`, `high_w5 = H5`, origin `L0`, `H1`.

### 6.2 Длительность и смена

Правило (одно, заморожено здесь):

1. `5-down` / `5-up` живут с бара подтверждения L5 / H5 **пока не сменены**.
2. Новый **прошедший** count (любая ориентация) **заменяет** предыдущий с своего бара подтверждения.
3. Новый count **не прошёл** фильтр, либо 3 ≠ 5, либо конфликт: на **баре события** метка `unreadable`; со **следующего** бара — `none`, пока не появится новый прошедший count. `unreadable` **не** держать бесконечно.
4. Снятие уже действующего прошедшего count более поздним пивотом, который «выбивает» структуру (5-down: подтверждённый swing high `> H0` **или** бар с `high >= H0` после L5; 5-up: swing low `< L0` **или** бар с `low <= L0` после H5): на баре снятия `unreadable`, затем `none`. Это не торговый выход S-1; это сброс лабораторной метки.

Рекомендация штаба соблюдена: новый прошедший count заменяет; неуспешный новый count → `unreadable` на баре отказа, затем `none`.

### 6.3 Конфликт на одном баре

Если на одном баре одновременно применились бы прошедшие `5-up` и `5-down`: метка `unreadable` (конфликт). Приоритета «лонг важнее» не изобретать. Событие в `n_unreadable`. Со следующего бара — `none`, если новый прошедший count сразу не заменил.

Незаконченный zigzag без события отказа — `none`, не `unreadable`. «Запил» без события 3 ≠ 5 / filter-fail сам по себе не держит `unreadable` часами: только бар события, затем `none`.
