# K-0 — каркас replay без стратегии

Статус: Knowledge Candidate / Контур-кандидат. Не Foundation. Не канон AICM. Не Hermes. Не live. Не Bitget-бот.
Дата: 2026-08-30
Источник: официальные URL (data.binance.vision + binance-public-data README), дата доступа 2026-08-30
Provenance: смотрели индекс Vision, raw README GitHub, HEAD zip/CHECKSUM, S3-листинг ключей, PDF Vision Dataset Terms. Репозиторий не клонировали. Zip-датасеты klines не скачивали (тело zip не GET). Числа метрик не считали. Каталог баров не строили.

## Что это

K-0 — **каркас replay без стратегии**. Проверка каркаса: читаются ли публичные свечи Binance Vision и считаются ли метрики против **двух baseline**. Это не замена Bitget. Это не торговый контур архитектора (Bitget BTC/USDT, Wave-1/Wave-2). Это не live. Капитал = 0. P&L лаборатории не является вердиктом по знанию AICM.

Единственные «стратегии» K-0: (1) buy&hold 100% long от первого бара окна до последнего; (2) no-trade. Входов, выходов, размера, стопов нет.

## Как читать zip (процедура Tester, не дамп кода)

1. Скачать monthly zip (предпочтительно) или daily zip по проверенному шаблону URL плюс sibling `.CHECKSUM` из той же папки. Monthly: `https://data.binance.vision/data/spot/monthly/klines/BTCUSDT/1h/BTCUSDT-1h-YYYY-MM.zip`. Daily: `https://data.binance.vision/data/spot/daily/klines/BTCUSDT/1h/BTCUSDT-1h-YYYY-MM-DD.zip`. CHECKSUM: то же имя + `.CHECKSUM`.
2. Проверить SHA256 zip против CHECKSUM. README: `sha256sum -c <file>.zip.CHECKSUM` (Linux) / `shasum -a 256 -c …` (macOS). Формат CHECKSUM (снято GET 88-байтного sibling, не zip): `<64 hex>  <zip-filename>`.
3. Распаковать: один CSV на месяц/день, без header row.
4. Разобрать 12 колонок в порядке README. `Open time` → datetime UTC. Если README/величина timestamp говорят µs (SPOT с 2025-01-01) — конвертить как микросекунды; иначе миллисекунды. Не нормализовать молча.
5. Конкатенировать, сортировать по `open_time`, удалить **точные дубликаты timestamp**. Assert шаг 1h: `3600000` ms (до 2025-01-01) либо `3600000000` µs (SPOT с 2025-01-01). Разрывы **флагировать, не заполнять**. Gap = соседние `open_time` с дельтой ≠ 1h. Пробелы отчёт, не выдумка.
6. Окно = `[first open_time, last open_time]` **фактически прочитанной** конкатенированной серии (UTC, inclusive по `open_time`). В этой спецификации красивое окно не выбирается. Даты первой/последней свечи: **не снято / прогон не делали**.
7. Локальный каталог баров на диске лаборатории (CSV или Parquet), не GitHub. Соглашение пути: `local/data/binance-vision/BTCUSDT/1h/`.

Не скачивать zip «чтобы заполнить spec числами». Метрики — только из прогона Tester.

## Метрики (определения; чисел нет)

Все метрики считает Tester по фактической серии. Здесь только формулы. Любое число доходности, просадки, числа баров, дат первой/последней свечи в отчёте K-0 без прогона = стоп.

- **Окно:** `open_time` первого и последнего бара после concat+dedupe, UTC, inclusive. Значение: **не снято / прогон не делали**.
- **Число баров:** count уникальных 1h баров после dedupe. Отдельно — count обнаруженных gap. Оба: **не снято / прогон не делали**.
- **Доходность (buy&hold):** `close_last / close_first - 1`, где `close_first` / `close_last` — `Close` первого и последнего бара окна. Комиссии в K-0 = 0 по определению каркаса. Funding N/A (spot). Число: **не снято / прогон не делали**.
- **Макс. просадка (buy&hold):** equity = 100% long с бара 1 до последнего, mark-to-close. Пик — running max `Close` до t включительно. Просадка в t: `(peak_close_to_t - close_t) / peak_close_to_t`. Макс. просадка = max по t этой величины.
  - `peak_t = max_{s ≤ t} close_s`
  - `DD = max_t (peak_t - close_t) / peak_t`
  - Число: **не снято / прогон не делали**.
- **No-trade:** equity константа `1.0`; доходность = `0`; макс. просадка = `0`. Это второй baseline, не шутка.
- Опциональная диагностика (не критерии успеха): доля missing-bar (gaps / ожидаемые шаги 1h в окне), число checksum fail, timezone (ожидается UTC). Числа: **не снято / прогон не делали**.

K-0 не имеет entries, exits, size, stops.

## Вход / выход

**Вход:** список Vision zip URL (или диапазон дат, разворачиваемый в эти URL по шаблонам выше), `symbol=BTCUSDT`, `interval=1h`, `market=spot`.

**Выход отчёта Tester (позже, не этот файл):** markdown с полями window, `n_bars`, `n_gaps`, buy&hold return, buy&hold max DD, no-trade return=`0`, no-trade DD=`0`, checksum ok, путь локального каталога. Числа — только из прогона.

**Выход каркаса:** локальный каталог баров, читаемый следующими контурами (K-1, затем S-*).

## Успех / стоп

- **Успех:** свечи читаются с `data.binance.vision`, checksum сходится, метрики считаются по формулам выше, оба baseline есть.
- **Стоп:** нет данных (404 / пустой zip / checksum fail) **или** числа из головы.

## Вне скоупа

Не входит: входы по волнам/новости; слои Андреев/Радченко/Миша/TE/Zatulyviter/Армен/Антон; FRED; yfinance; Stooq; ключи бирж; Bitget-бот; live; Nautilus; LEAN; Tardis; Databento; VectorBT PRO; Freqtrade/Jesse/Hummingbot; гибрид слоёв. Стратегии S-* штаб назовёт после K-0.

## Как работает механизм

Pipeline: **download → checksum → parse → concat → gap report → metrics vs two baselines**.

Tester по списку URL (monthly предпочтительнее daily) забирает zip+CHECKSUM, сверяет SHA256, парсит CSV без header в 12 колонок README, приводит `Open time` к UTC с учётом ms/µs, склеивает, сортирует, снимает exact duplicate timestamps, считает 1h-шаг и пишет gaps в отчёт без fill, затем на `[first, last] open_time` считает buy&hold (return и max DD по close) и no-trade (0 / 0). Каталог баров остаётся на диске лаборатории.

Псевдокод (не реализация):

```
urls = expand(range, pattern monthly|daily + .CHECKSUM)
for zip, cs in urls:
    get(zip); get(cs); sha256sum -c cs or STOP
bars = concat(parse_csv(unzip(zip)))  # 12 cols, UTC, µs|ms
bars = sort(drop_dup_open_time(bars))
gaps = flag(delta(open_time) != 1h); no fill
window = [min(open_time), max(open_time)]
report bh_ret, bh_dd, nt_ret=0, nt_dd=0, n_bars, n_gaps
store catalog local/data/binance-vision/BTCUSDT/1h/
```
